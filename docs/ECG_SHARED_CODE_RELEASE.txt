## Attendee workflow

- One ECE-issued personal code identifies a delegate's committee-country seat or an individual chair's committee and role. ECE remains the code authority and the owner of orders, menus, rounds and staff accounts.
- KAMUN verifies the code through a private server endpoint and saves its own Supabase session and nonsecret profile. It never persists the reusable ECE code or login pepper.
- On return, KAMUN displays saved information immediately and verifies access in the background. A network failure preserves cached information; confirmed expired/revoked access clears the profile and content cache. Protected server operations still require a valid binding.
- Opening ECE requests a 60-second, single-use ticket. ECE strips it from the URL, exchanges it for its normal HTTP-only cookie and replaces any previously remembered account. An invalid handoff does not fall back to the old account.
- ECE cookies persist until the configured participant_session_until expiry (the seed currently uses 16 November 2026 at 22:59 UTC), revocation or logout. Browser storage clearing/private browsing can remove saved sessions.
- Signing out from KAMUN revokes ECE sessions and unused tickets opened from that KAMUN login, then signs out the local Supabase session. Other devices' independent logins are unaffected. A pending logout is saved and retried on return; failed logout is not reported as successful.
- Successful code changes revoke the preceding linked ECE sessions before binding the new identity. Old KAMUN-only chair/member codes remain transitional access and cannot open the shared ECE flow. Organiser and staff credentials remain separate.
